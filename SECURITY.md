# Модель угроз и защитные меры

Документ описывает, от чего SyncMob защищает, от чего — нет, и где именно в коде
находится каждая проверка.

---

## 1. Что защищается

| Угроза | Защита | Где |
|---|---|---|
| Пассивное прослушивание сети | Noise XX + ChaCha20-Poly1305, прямая секретность | `desktop/src/net/session.rs`, `mobile/.../crypto/Noise.kt` |
| Подмена соединения (MITM) при первом контакте | Код сверки из хеша рукопожатия, подтверждаемый обеими сторонами; либо QR с ключом out-of-band | `security/fingerprint.rs`, `security/Fingerprints.kt` |
| Подключение постороннего устройства | Список доверия: неизвестный ключ не может прислать ни текст, ни файл | `engine/mod.rs::on_message`, `engine/Engine.kt::onMessage` |
| Выход за каталог загрузок (`../../`) | Жёсткая очистка имени + карантин + проверка родителя | `util.rs::sanitize_filename`, `util/SafeFiles.kt` |
| Подмена содержимого файла | SHA-256 из предложения проверяется перед публикацией файла | `engine/transfer.rs`, `engine/Transfers.kt` |
| Переполнение диска | Лимит размера в предложении + проверка при каждом блоке | там же |
| Исчерпание памяти длиной кадра | Префикс длины проверяется до выделения буфера | `net/session.rs`, `net/Session.kt` |
| Флуд подключениями | 10 рукопожатий в минуту с адреса, максимум 16 соединений | `engine/mod.rs::ConnGuard`, `Engine.kt::ConnGuard` |
| Флуд маяками | 4 маяка в секунду с адреса, максимум 128 пиров | `net/discovery.rs`, `net/Discovery.kt` |
| Случайный выход в интернет | Режим «только локальная сеть»: адреса вне RFC1918/link-local/ULA отклоняются | `util.rs::is_lan_addr`, `SafeFiles.isLanAddress` |
| Чтение приватного ключа с диска | Windows: Argon2id + XChaCha20-Poly1305 под паролем. Android: AES-256-GCM в Android Keystore | `security/keystore.rs`, `crypto/Identity.kt` |
| Тихая подмена списка доверия | Список зашифрован и аутентифицирован ключом, производным от приватного ключа | `security/trust.rs`, `security/TrustStore.kt` |
| Утечка ключа в логи | `Debug`/`toString` идентичности выводят `<redacted>` | `keystore.rs`, `Identity.kt` |
| Утечка ключа через бэкап Android | `allowBackup=false` + явные правила исключения | `AndroidManifest.xml`, `xml/data_extraction_rules.xml` |
| Тайминг-атака на сравнение ключей | Сравнение за постоянное время | `subtle::ConstantTimeEq`, `Noise.constantTimeEquals` |

## 2. Что НЕ защищается

Формулировки намеренно прямые — так надёжнее, чем обтекаемые.

* **Код, выполняющийся от вашего имени при разблокированном приложении.**
  На Windows после ввода пароля приватный ключ находится в памяти процесса.
  На Android ключ не извлекаем из Keystore, но само приложение может им
  пользоваться, пока устройство разблокировано.
* **Физический доступ к разблокированному устройству.**
* **Метаданные в локальной сети.** Если включено объявление в сети, имя
  устройства и его публичный ключ видит вся подсеть. Объявление можно выключить
  в настройках — тогда подключаться придётся по адресу вручную.
* **Скомпрометированное сопряжённое устройство.** Сопряжение — это доверие.
  Ограничивают ущерб: подтверждение каждого файла (если не включён автоприём),
  проверка хеша, лимит размера, запись только в папку загрузок. Но сопряжённый
  пир может слать вам файлы и сообщения, пока вы его не заблокируете или не удалите.
* **Пользователь, не сверивший код.** Если нажать «Подтвердить», не посмотрев
  на второй экран, защита от MITM не работает. Поэтому код показан крупно,
  а рядом — предупреждение.
* **Анализ трафика.** Размеры и тайминги кадров не маскируются; наблюдатель
  видит, что передаётся файл и примерно какого размера.

## 3. Ключевые решения и почему так

### Noise XX, а не TLS

XX даёт взаимную аутентификацию по «сырым» статическим ключам без PKI. Для сети
без центра сертификации это проще и честнее, чем самоподписанные сертификаты:
доверие выражается ровно одним фактом — «этот 32-байтный ключ мы один раз
подтвердили». Побочный плюс: XX скрывает статический ключ инициатора от
пассивного наблюдателя.

### Сопряжение требует подтверждения обеих сторон

Односторонний «TOFU» (доверие при первом контакте) сделал бы MITM незаметным.
Здесь оба пользователя видят один и тот же восьмизначный код, выведенный из хеша
рукопожатия. Атакующий вынужден вести два разных сеанса, и совпасть оба кода не
могут.

### Приватный ключ на Windows защищён паролем, а не DPAPI

DPAPI прозрачен для любого кода, работающего от имени того же пользователя.
Argon2id (64 МиБ, 3 прохода) + XChaCha20-Poly1305 даёт реальную защиту от чтения
файла профиля. Цена — ввод пароля при запуске. Пароль можно не задавать,
но тогда интерфейс постоянно показывает предупреждение.

### Файл сначала в карантин, потом в загрузки

Пока файл не проверен по SHA-256, он лежит в каталоге приложения под именем из
идентификатора передачи. Ничего, что контролирует пир, не попадает в файловую
систему до проверки. Ошибка на любом шаге удаляет частичный файл.

### Автоприём файлов выключен по умолчанию

Включается отдельно для каждого устройства, с явным предупреждением в интерфейсе.

### Kotlin-реализация Noise написана вручную — и поэтому обвязана тестами

На Android нет `snow`. Рукописная криптография — риск, поэтому она привязана к
проверенной реализации тремя способами: пошаговый Rust-эталон, проверенный против
`snow` в обеих ролях; тест-векторы примитивов, сгенерированные Rust-стороной;
и утилиты реального рукопожатия по сокету. См. раздел 6 в `PROTOCOL.md`.

## 4. Проверка состояния защиты

```bash
# Rust: 70 тестов, включая сквозной обмен файлами между двумя узлами
cd desktop && cargo test

# Rust: совместимость рукописной реализации Noise со snow
cd desktop && cargo test --test noise_reference

# Kotlin: 38 тестов, включая тест-векторы, совпадающие с Rust побайтово
cd mobile && ./gradlew :app:testDebugUnitTest

# Реальное рукопожатие между модулями
cd desktop && cargo run --example interop_responder -- 45999
```

## 5. Если что-то пошло не так

* **Устройство потеряно** — удалите его из списка доверия на всех остальных
  («Забыть устройство»). Ключ перестаёт что-либо значить немедленно.
* **Подозрение на перехват** — коды сверки не совпали: не подтверждайте,
  разберитесь с сетью. Это не ложное срабатывание «просто так».
* **Забыт пароль от ключа (Windows)** — восстановления нет by design. Удалите
  `identity.json` и `trust.json` из каталога профиля, создайте устройство заново
  и пройдите сопряжение. Путь к профилю показан в настройках.
* **Сброшены учётные данные экрана блокировки (Android)** — ключ в Keystore
  становится нерасшифровываемым. Приложение сообщит об этом явно и предложит
  сброс личности, а не создаст молча новый ключ.
