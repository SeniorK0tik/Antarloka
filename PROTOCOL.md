# Протокол SyncMob, версия 1

Единая спецификация для обоих модулей. Rust-реализация — `desktop/src/proto.rs`,
Kotlin-реализация — `mobile/app/src/main/java/org/syncmob/mobile/proto/Protocol.kt`.
Любое изменение здесь нужно вносить в оба файла одновременно.

---

## 1. Обнаружение устройств (UDP)

| Параметр | Значение |
|---|---|
| Порт | `45820/udp` |
| Multicast-группа | `239.255.79.20` |
| Broadcast | `255.255.255.255` + broadcast-адрес каждого интерфейса |
| Период | 3 с |
| TTL записи о пире | 15 с |
| Максимальный размер датаграммы | 512 байт |

Тело — JSON:

```json
{"m":"SYNCMOB","v":1,"pk":"<base64 X25519 pub>","name":"Мой ПК","port":45821,"platform":"windows"}
```

**Маяк не аутентифицирован и это осознанное решение.** Он содержит только
публичные данные и служит подсказкой «здесь, возможно, есть устройство». Подделать
его может кто угодно, поэтому маяк никогда не даёт прав: он лишь наполняет список
«устройства рядом», а доверие возникает только после рукопожатия Noise и явного
сопряжения.

Правила приёма (обе реализации):

* размер ≤ 512 байт, иначе датаграмма отбрасывается без разбора;
* `m` и `v` должны совпадать;
* `pk` — ровно 32 байта после base64;
* `port` в диапазоне 1…65535;
* адрес пира берётся **из источника UDP-пакета**, а не из тела — маяк не может
  направить нас на третий хост;
* не более 4 маяков в секунду с одного адреса;
* собственный маяк, вернувшийся из сети, игнорируется.

## 2. Транспорт (TCP)

Порт по умолчанию — `45821/tcp`.

### 2.1 Рукопожатие

```
Noise_XX_25519_ChaChaPoly_BLAKE2s
prologue = "SyncMob/1"
```

```
-> e                       (32 байта)
<- e, ee, s, es            (96 байт)
-> s, se                   (64 байта)
```

Каждое сообщение рукопожатия обёрнуто в кадр `u32be длина || тело`.
Полезная нагрузка во всех трёх сообщениях пустая.

Что даёт рукопожатие:

1. пару шифр-состояний ChaCha20-Poly1305 с прямой секретностью;
2. **статический публичный ключ пира** — именно он проверяется по списку доверия;
3. **хеш рукопожатия** — он одинаков у обеих честных сторон и не может совпасть
   у обеих сторон при атаке «человек посередине». Из него выводится код сверки.

### 2.2 Кадры после рукопожатия

```
u32be  длина шифротекста   (16 … 65535)
bytes  шифротекст          (ChaCha20-Poly1305, тег 16 байт включён)
```

Расшифрованный открытый текст:

```
u8     тип сообщения
bytes  полезная нагрузка   (JSON для управляющих, бинарь для FILE_CHUNK)
```

Длина проверяется **до** выделения памяти — префикс длины контролируется атакующим.

## 3. Типы сообщений

| Код | Имя | Нагрузка |
|---|---|---|
| `0x01` | HELLO | `{"name","version","platform"}` |
| `0x02` | PING | пусто |
| `0x03` | PONG | пусто |
| `0x10` | PAIR_REQUEST | `{"name","platform"}` |
| `0x11` | PAIR_ACCEPT | пусто |
| `0x12` | PAIR_REJECT | `{"reason"}` |
| `0x20` | TEXT | `{"id","ts","text"}` |
| `0x21` | TEXT_ACK | `{"id"}` |
| `0x30` | FILE_OFFER | `{"id","name","size","sha256","mime"}` |
| `0x31` | FILE_ACCEPT | `{"id"}` |
| `0x32` | FILE_REJECT | `{"id","reason"}` |
| `0x33` | FILE_CHUNK | `id(16) \|\| offset(u64be) \|\| данные` |
| `0x34` | FILE_DONE | `{"id","sha256"}` |
| `0x35` | FILE_ERROR | `{"id","reason"}` |
| `0x36` | FILE_CANCEL | `{"id","reason"}` |

`id` — 128-битный идентификатор передачи в hex (32 символа).

### Лимиты, проверяемые при разборе

| Что | Предел |
|---|---|
| Управляющий JSON | 16 КиБ |
| Текст сообщения | 4096 символов |
| Имя устройства | 64 символа |
| Имя файла (до очистки) | 255 символов |
| Размер файла | 2^40 байт (жёсткий потолок, плюс настраиваемый лимит) |
| Блок FILE_CHUNK | 32 КиБ данных |
| Одновременных подключений | 16 |
| Одновременных приёмов файлов | 16 |

### Сообщения, разрешённые до сопряжения

Только `HELLO`, `PING`, `PONG`, `PAIR_REQUEST`, `PAIR_ACCEPT`, `PAIR_REJECT`.
Всё остальное от несопряжённого пира — повод закрыть соединение. Правило
реализовано **независимо на обеих сторонах**: `Message::allowed_before_pairing`
в Rust и `Message.allowedBeforePairing()` в Kotlin.

## 4. Сопряжение

```
         A                                   B
         |--- TCP + Noise XX --------------->|
         |<------------- рукопожатие --------|
         |                                   |
   показывает код                      показывает код
   8 цифр из hash                      8 цифр из hash
         |                                   |
   пользователь                        пользователь
   сверяет и жмёт                      сверяет и жмёт
   «Подтвердить»                       «Подтвердить»
         |------------ PAIR_ACCEPT --------->|
         |<----------- PAIR_ACCEPT ----------|
         |                                   |
   ключ записан в              ключ записан в
   список доверия              список доверия
```

Сопряжение завершается, **только если подтвердили обе стороны**. Одностороннего
согласия недостаточно. Неотвеченный запрос закрывается через 180 секунд.

### Код сверки (SAS)

```
sas = BLAKE2s-256("SyncMob/1 sas" || handshake_hash)[0..8] as u64be mod 10^8
```

Формат: `1234 5678`. Хеш рукопожатия фиксирует оба статических ключа, оба
эфемерных ключа и prologue, поэтому атакующему, ведущему два разных сеанса,
пришлось бы угадать совпадение — вероятность 10⁻⁸ на попытку, а попытки
ограничены по частоте и видимы пользователю.

### Отпечаток ключа

```
fingerprint = BLAKE2s-256("SyncMob/1 fingerprint" || pubkey)[0..16]
```

Формат: `4BB0 BFBF 3E51 1937 3A86 682B A602 2DB9`.

### Короткий идентификатор

```
device_id = BLAKE2s-256("SyncMob/1 device-id" || pubkey)[0..8]
```

Только для отображения и в качестве ключа в таблицах. Никогда не используется
для проверки прав.

### QR-ссылка

```
syncmob://pair?v=1&pk=<base64url без padding>&host=<IPv4>&port=<порт>&name=<percent-encoded>
```

Телефон, отсканировавший код, знает ожидаемый ключ **до** подключения. Если после
рукопожатия предъявленный ключ отличается — это активная атака, соединение
разрывается с явным предупреждением.

## 5. Передача файла

```
отправитель                                 получатель
    |-- FILE_OFFER (имя, размер, sha256) ------>|
    |                                    пользователь подтверждает
    |<----------------- FILE_ACCEPT ------------|
    |-- FILE_CHUNK (offset=0)    -------------->|
    |-- FILE_CHUNK (offset=32768) ------------->|
    |   ...                                     |
    |-- FILE_DONE -----------------------------> (уже проверено)
```

Правила получателя:

1. блоки строго по порядку — `offset` обязан равняться числу уже принятых байт;
2. суммарный объём не может превысить заявленный размер;
3. данные пишутся в карантинный файл внутри каталога приложения, имя — по
   идентификатору передачи, а не по строке от пира;
4. по достижении заявленного размера считается SHA-256 и сравнивается с
   `FILE_OFFER`; при несовпадении файл удаляется;
5. только после успешной проверки файл переносится в папку загрузок под
   очищенным именем, причём существующие файлы никогда не перезаписываются
   (добавляется ` (1)`, ` (2)`, …).

Очистка имени файла (одинаковая в обоих модулях):

* берётся только последний компонент пути по `/` и `\`;
* удаляются управляющие символы и `< > : " / \ | ? *`;
* срезаются хвостовые точки и пробелы (Windows делает это молча);
* `.` и `..` заменяются на `received_file`;
* зарезервированные имена Windows (`CON`, `NUL`, `COM1`…) получают префикс `_`;
* длина ограничена 120 байтами с сохранением расширения.

## 6. Проверка совместимости реализаций

Kotlin-реализация Noise написана вручную (на Android нет `snow`), поэтому она
привязана к Rust тремя уровнями проверок:

1. `desktop/tests/noise_reference.rs` — пошаговая реализация по спецификации,
   которая проверяется против `snow` в обеих ролях. Kotlin — её дословный перевод.
2. `mobile/.../CrossImplementationVectorsTest.kt` — тест-векторы (BLAKE2s, HMAC,
   HKDF, X25519, отпечатки, коды сверки), сгенерированные Rust-стороной. Любое
   расхождение примитивов ломает тест, а не пользователей.
3. Утилиты `cargo run --example interop_responder` / `interop_initiator` —
   реальное рукопожатие по сокету с любым клиентом.

Регенерация векторов:

```bash
cd desktop
cargo test --test noise_reference --no-default-features print_vectors -- --ignored --nocapture
```
